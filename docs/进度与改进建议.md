## 二、还差什么（按优先级）

### P0 · 补资料文案（最大的价值缺口）

3133 条。这是**唯一能让"教育属性"成立**的东西 —— 现在的描述是：
"拼图游戏" → 玩家拼完看一眼面积就关了。

补完之后才是：**拼完能学到这个县有什么、为什么叫这个名字、有什么冷知识**。

### P1 · 关卡 blurb 的人工优化

现在多关地图的 blurb 是自动生成的"按行政类型自动分组：这个市的城区部分（市辖区）（12 个）"。
成都那种人工 blurb 读起来完全不同：

> "成都的'心脏'——锦江、青羊、金牛、武侯、成华五个老城区。它们面积都很小
> （最小的锦江区只有 62 平方公里），边界犬牙交错，是全市最难拼的一组。"

**这是"游戏感"的关键之一**，但只能逐市人工写。

### P2 · 体验与产品化

| 缺什么 | 影响 |
| --- | --- |
| 没有跨地图的**总进度**展示 | 玩家不知道自己拼了多少、还差多少 |
| 没有**分享**能力 | 玩完的成就感无处释放（这是社交传播的唯一入口） |
| 没有**成就/徽章** | 缺少长期目标 |
| 没有**每日挑战** | 缺少回访理由 |
| 只有中文界面 | 无法面向更广用户 |
| 桌面端为主（已做窄屏降级，但没做过真机验证） | 手机体验未知 |

### P3 · 工程债（不紧急，但迟早要还）

## 三、怎么省 token 跑完（这是我的作战方案）

### 3.1 已经省下的（本轮建立的流水线）

| 环节 | 老做法 | 现在 | 省 |
| --- | --- | --- | --- |
| 抓素材 | 一次一个区县，~22 轮 tool call + 55 KB 上下文 | `facts-batch` 一条命令一个市，**0.6 KB 摘要** | ~96% |
| 判断 | 我逐条读网页 | 子代理读素材、只回 3 行 | 主上下文 ~0 |
| 核对 | 我肉眼 | `facts-verify` 机械比对 evidence | 主上下文 ~0 |
| 落笔 | 我写落笔脚本 | `--apply` 自动落笔 | ~96% |
| 调规则 | 反复重抓（把站点打限流） | **磁盘缓存**，重抽 0.1 s | 100%（零联网） |
| 验证 | 跑全量 363 张（8 分钟） | **抽样 8~20 张（8~24 秒）** | ~95% |

### 3.2 补 3133 条文案的推荐节奏

```bash
# 一轮处理 6~8 个市（一个省的量级 ≈ 10~20 个市，分 2~3 轮）
# ① 批量抓取（串行 + 间隔，避免限流；已抓过的走缓存）
for m in <市1> <市2> …; do node tools/facts-batch.js --map=$m --delay=1800 --prompt; done
# ② 一次 workflow 并行委派（每个子代理只回 3 行摘要）
# ③ 逐个落笔 + 抽样自检
for m in <市1> …; do node tools/facts-verify.js --map=$m --in=out/verify-$m.json --apply; done
node tools/test-maps.js 2>&1 | tail -3
```

**预期成本**（按前 8 个市的实测推）：

| 指标 | 每市 | 全国 ≈ 350 个市 |
| --- | --- | --- |
| 我的上下文增量 | ~2–4 KB（摘要与决策） | **~1 MB** |
| 抓取耗时 | 15–45 s（缓存命中 0.2 s） | 2–4 小时（可后台） |
| 轮数 | 6–8 个市/轮 | **45–60 轮** |

**这是可完成的**（之前的做法要 100+ 轮且每轮 8 KB）。

### 3.3 三条省 token 的铁律（本轮血泪换的）

1. **绝不把网页原文或长 JSON 读进主上下文** —— 让脚本抽句子、让子代理判断
2. **迭代时抽样验证，不要全量** —— `--only-maps=<ids> --only-suite=smoke`
3. **长任务不要干等** —— 要么后台 + 定期看日志，要么拆小批；等的时候做别的事

### 3.4 还要注意的一个现实问题

**抓取源（百科镜像）会限流**。实测：一次抓 18 个县会把站点打到 IP 级封禁，恢复要 10~30 分钟。
所以：
- 每批 3~5 个、间隔 ≥5 s、批之间 sleep 25 s
- 优先跑**缓存里已有页面**的市（`--delay=0` 重抽，零联网）

## 四、怎么更吸引人（我的建议，按性价比排序）

### 4.1 高性价比：不做这些，内容就浪费了

**① 分享成绩（最高优先，成本最低，收益最大）**

玩完一关能生成一张图/一段文字分享出去：
> "我在《中国地图拼图》拼完了四川省 · 用时 4:32 · 一次都没用提示"

现在的流程是：拼完 → 结算画面 → **关掉，什么都没留下**。
加一个"生成分享图"（Canvas 画一张带地图缩略图+成绩的卡片）就能解决社交传播，**几乎不需要改引擎**。

**② 跨地图总进度 + 成就**

现在玩家只能看到"当前这张图拼到哪"。加：
- "你已拼完 62 / 363 张地图"（一个进度条，放在地图选择器旁边）
- 徽章：`省级全通`（34/34）、`拼完一个省`、`零提示通关 10 关`、`中国全图完成`

**成就感来自"看得见的积累"** —— 这正是这个项目最有优势的地方（363 张地图 = 天然的大量进度）。

**③ 信息卡做成"图鉴"**

补完 3133 条文案后，加一个"已收集的资料卡"页面：
每拼完一个区县，它的资料卡就进图鉴；点开能翻阅。

> **这一步会把这个游戏从"拼图玩具"变成"地理百科游戏"** ——
> 也是唯一能让"教育"这个卖点真正成立的路径。
> 而且它天然驱动"想集齐"的动机。

### 4.2 中等成本：提升单局体验

| 建议 | 说明 | 改动范围 |
| --- | --- | --- |
| **连击** | 连续拼对不失误 → 连击数 + 音效升调；错一次清零 | 引擎小改 |
| **倒计时模式** | 可选"限时挑战"，给每关一个目标时间 | 引擎小改 |
| **首字母提示** | 卡住时高亮"下一块拼这里"（现在只有"提示"整块给出） | 引擎小改 |
| **难度分级** | 现在所有地图难度一样（就是碎片数）。可按名称显示/隐藏、按碎片数分级 | 引擎中等 |
| **关卡主题命名** | 把"市辖区/县"改成有吸引力的名字，如"中心城区""山水县城" | 内容活 |

### 4.3 需要慎重：别为了"上瘾"伤害产品

**不建议做**：体力值、强制登录、广告激励、抽卡。
理由：这个项目的价值是"认识中国的地理"，加这些东西会立刻把气质做low，
而且会引入合规负担（用户数据、未成年人保护）。

**氛围类建议**（符合调性）：
- 拼完一省解锁一张该省的"地图海报"（用已有边界数据生成，零额外素材）
- 拼图完成时的地图"上色"动画（现在已有颜色，可以做成渐变晕染）

### 4.4 一句话总结我的判断

> **这个项目目前的短板不是技术，是内容与反馈。**
> 技术骨架（363 张地图 + 自动面积 + 流水线）已经能支撑一个真产品；
> 但玩家现在拼完一个国家也不知道自己想干嘛 ——
> **补齐资料文案 + 加总进度 + 加分享**，这三件事就能把它从"demo"变成"能传播的游戏"。

## 五、如果只做三件事

按投入产出比排序：

1. **补四川以外的资料文案**（工具链已就绪，45~60 轮可完成）

2. **加"总进度 + 成就"**（1 轮工作量）
   → 让玩家看见积累，363 张地图的价值立刻显现
3. **加"生成分享图"**（1 轮工作量）
   → 唯一的传播入口，成本极低
