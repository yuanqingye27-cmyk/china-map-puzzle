# 玩法设计与传播机制（借鉴 + 原创）

> 目标：**让玩家知道自己在干嘛，并且想告诉别人。**
> 原则（沿用你定的三条）：普适性高、底层结构简单正确、分类科学。
> 每一节都标了「改动范围」——决定它是"改几行"还是"要重做引擎"。

---

## 一、先看清我们的独特资产

分析羊了个羊这类游戏时，容易只看到"难、分享、每日一关"。
但它们真正的前提是**内容极轻**（一关就是几十张牌），所以能天天换。

**我们的资产恰好相反，而且更强**：

| 资产 | 数量 | 意味着什么 |
| --- | --- | --- |
| 地图 | **363 张**（还在扩） | 天然的大量关卡，不用设计 |
| 资料卡 | **3214 条**（待补文案） | 天然的大图鉴，**"收集"这件事不需要写代码** |
| 层级 | 中国 → 省 → 市 → 区县 | 天然的"成就阶梯"（我拼完了我的省 → 我的国） |

> **结论：不该抄"难"，该抄"收集 + 炫耀 + 每日"这三件事，
> 而我们的底子比它们更适合做收集。**

## 二、羊了个羊为什么能传播（拆开看机制）

| 机制 | 它怎么做的 | 我们能不能抄 | 对应实现 |
| --- | --- | --- | --- |
| **极低门槛 + 极高天花板** | 第一关 3 秒过，第二关过不去 | ✅ 抄 | 我们的第一关本来就简单；难的是"大省 18 个区县" |
| **每日一关** | 全国玩家同一天同一局 | ✅ 抄 | 用 adcode 做种子选一张地图 + 一个关卡顺序 |
| **排行榜（好友 + 全国）** | 攀比产生回访 | ✅ 抄（可简化） | 先做"本地最佳成绩"，再做服务端 |
| **失败的挫败感 → 分享冲动** | "这关根本过不去"是社交货币 | ⚠️ 部分抄 | 我们不追求"过不去"，但"零提示通关"可以成为炫耀点 |
| **地域认同** | 没有 | ✅ **我们更强** | "拼出我的家乡"是天然分享动机 |
| 复活/道具/看广告 | 变现手段 | ❌ 不抄 | 会破坏"认识中国地理"的产品气质 |

**一句话**：羊了个羊靠"难"，我们靠"多"和"这是我的家乡"。

## 三、原创方向（我认为最适合这个项目的三条）

### 方向 1 · 「拼出我的家乡」—— 最强的分享动机 ⭐⭐⭐

**机制**：进入时让玩家选/搜自己的家乡（省/市/县），
拼完生成一张带家乡地图的卡片：

> "这是我拼出来的乐山市 · 11 个区县 · 用时 4:32"

**为什么它会传播**：地域认同是最廉价的分享理由。
人们会为了"我是XX人"转发，而不是为了"我玩了个游戏"。

**改动范围**：小。分享卡片已经能画地图轮廓了（`js/share.js`），
只要把"当前地图"换成"玩家选的家乡地图"。

### 方向 2 · 「每日一图」—— 最低成本的回访机制 ⭐⭐⭐

**机制**：
```js
// 当天日期做种子，所有人抽到同一张地图 + 同一个关卡顺序
const seed = YYYYMMDD;
const mapIndex = seed % 全部地图数;
```
- 每天 0 点换一张，**全国玩家玩同一张**
- 拼完给一个"今日打卡"N 天的连续天数
- 不引入新内容、不需要服务端

**为什么有效**：不需要内容团队，天然制造"大家都玩过"的话题感。
连续天数（streak）是回访的最强钩子之一，而且**它不靠推送给压力** —— 玩家自己惦记。

**改动范围**：小。抽地图 + 一个 localStorage 打卡记录。

### 方向 3 · 「地理图鉴」—— 把教育属性变成收集欲 ⭐⭐⭐

**机制**：每拼完一个区县，它的资料卡进图鉴；图鉴可按省/按类型筛选；
集齐一个省解锁一张"省级海报"。

**为什么这是本项目的护城河**：
- 别人抄不走（**3214 条资料卡是真的要一条条核实的**）
- 它把"拼图玩具"升级成"地理百科游戏"
- 收集进度天然驱动"再拼一个县"

**前提**：**资料文案得先补上**。图鉴是空的就没人收集。
→ 所以这是"内容驱动"的功能，和补文案这件事互为因果。

**改动范围**：中。新页面 + 现有 progress.js 已经有按省统计的能力。

## 四、可以顺手加的（低成本、见效快）

| 机制 | 效果 | 改动 |
| --- | --- | --- |
| **连击（combo）** | 连续拼对不失误 → 音效升调 + 数字跳动 | 引擎小改 |
| **限时挑战** | 每关给一个目标时间，超时有提示但不惩罚 | 引擎小改 |
| **首字母/首块高亮提示** | 现在只有"整块给答案"，可以降级成"高亮下一块该放哪" | 引擎小改 |
| **成绩对比** | 结算时显示"比上次快 12 秒" / "首次通关" | 引擎小改 |
| **今日最佳** | 本地记录当天最好成绩 | progress.js 加一个字段 |
| **省份进度环** | 地图选择器里每个省旁边显示 `3/21` | 宿主层渲染 |

## 六、明确不做的（避免把产品做坏）

| 不做 | 为什么 |
| --- | --- |
| 体力值 / 定时恢复 | 这是"不认识中国地理"的行业做法；我们的价值不靠成瘾 |
| 强制登录 / 手机号 | 引入合规负担（用户数据、未成年人保护），而且第一屏就走掉一半人 |
| 广告激励（看广告复活） | 破坏体验连续性，与"教育"定位冲突 |
| 排行榜内卷（全国前 100） | 需要服务端 + 防作弊；先用"本地最佳 + 好友对比"这类轻方案 |
| 抽卡 / 皮肤商城 | 与零依赖、双击即玩的定位冲突 |

> **判断标准**：任何机制加进来之后，问一句
> **"它让玩家更了解中国地理了吗？"** 答案是"没有"的，就不加。

## 七、给实现者的两条硬要求

1. **新机制必须先做成纯逻辑 + 可单测**
   （参考 `js/progress.js`、`js/share.js`：纯函数层 + 薄渲染层）
   —— 这样换平台时逻辑不用重写，且"算错了不会崩"的账本类逻辑能被测试钉住。
2. **不要破坏已有存档**
   新增存储键，不要动引擎每张地图的 `<id>-map-puzzle`
   （`js/progress.js` 就是这么做的，已有先例）。
