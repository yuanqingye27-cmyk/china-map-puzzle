## 二、怎么科学高效录入真实信息

### 2.1 核心原则：把"录入"拆成三层，各用不同策略

| 层 | 策略 | 现状 |
| --- | --- | --- |
| **能算的，不要抄** | 几何计算 | ✅ **已完成**：面积 3214/3214，从官方边界算，与公布值吻合 0.1~0.3% |
| **能批量的，不要手工** | 抓官方名录 | ⚠️ **部分可用**，见 2.2 |
| **只能人写的，才人写** | 人工核实 | ⚠️ 3132 条待补（tagline / funFact） |

**关键分工**：机器生产候选 → 机器校验 → **人只做最后一道判断**。
（这套已经建好了：`facts-batch` 抓取 + 子代理判断 + `facts-verify` 校验 + `--apply` 落笔）

### 2.2 实测可用的权威源（我逐个验过）

| 源 | 状态 | 能给什么 | 怎么用 |
| --- | --- | --- | --- |
| **民政部行政区划代码表**<br>`mca.gov.cn/mzsj/xzqh/` | ✅ **可直接解析**（实测 3226 行） | adcode + **官方标准名称** | 校对/补全名称；已有 3254 条地名表可与之对账 |
| **国家地名信息库**<br>`dmfw.mca.gov.cn/9091/dmgl/` | ⚠️ **我这里 404**（很可能境外 IP 被限） | 官方 API 含 `stname/detailsPub` —— **地名含义/由来**！ | **你在国内大概率能用**。如果通了，这是 funFact 的权威批量源 |
| **天地图官方** | ✅ 已用 | 边界几何（面积已由此算出） | 继续用 |
| 全国重点文物保护单位名录 | ⚠️ 几个镜像都不通 | 真实地标（国务院成批公布） | 值得再找入口；这是"地标"的最佳批量源 |

> **一个重要的现实**：我在境外，很多国内站点访问不了（实测 `xzqh.mca.gov.cn` 直接 000、维基百科 000）。
> **你在国内能访问的源比我多** —— 所以"探源"这件事你比我更适合做，
> 我负责把探到的源接成流水线。

### 2.3 "科学"的定义：每个字段都要能回答"你凭什么这么说"

资料卡现在只有四个字段（area / landmark / tagline / funFact），但**缺一个关键东西：来源与核验状态**。

建议扩展成：

```js
"510104": {
  area: 62.0,
  areaSrc: 'syq-3d',          // 口径标识：四川省情网"三调"数据
  landmark: '春熙路、太古里',
  landmarkSrc: 'baike:锦江区', // 来源
  tagline: '…',
  funFact: '…',
  verify: 'human',            // human=人工核实 / machine=机器抽取 / none=占位
  verifiedAt: '2026-09-17',
}
```

**为什么这一步是"科学"的关键**：
- 现在文件头写来源（我落笔时加的），但**字段级**没有来源
- 有了 `areaSrc` 才能回答"为什么这个区县面积和别的网站不一样"（口径不同）
- 有了 `verify` 才能在界面上诚实标注"这条是机器抽取，可能有误"
- 有了 `verifiedAt` 才知道哪条该复核

### 2.4 效率：把"一轮 3 小时"压到"一轮 30 分钟"

已经做到的：

| 手段 | 效果 |
| --- | --- |
| 磁盘缓存 | 同一页永不重抓（调规则时 0.1 秒） |
| 子代理判断 | 素材消化不进主上下文 |
| 机械校验 | 不用人逐条核对"有没有编" |
| `--apply` 自动落笔 | 不用逐条粘贴 |
| 抽样验证 | 从 8 分钟压到 24 秒 |

**还能再压的**：
- **众包**：把"核实一条资料卡"做成 GitHub Issue 模板（见第四节）
- **按省认领**：一个人认领一个省，比一个人做全国容易坚持

## 三、资料卡怎么更科学、更漂亮

### 3.1 科学（结构与诚实）

| 建议 | 为什么 |
| --- | --- |
| 字段级来源 + 核验状态 | 见 2.3。这是"可信"的基础 |
| 面积口径说明 | 成都已经这么做了（双流含托管区）——**把这个做法推广到所有条目** |
| 不确定就留白 | 现有铁律，保持 |

### 3.2 漂亮（信息层级）

现在的信息卡是"平铺四项"。建议分三层：

```
① 一眼看到（最重要的 2 个）
   地名 + 一句话定位（tagline）
   面积

② 想了解再看（展开）
   地标
   冷知识 / 名称由来

③ 想知道更多（链接）
   完整资料页（图鉴）
   数据来源与口径
```

**视觉上的三个具体改进**：
1. **地名下面加"所属"**（现在是"金牛区"，可以加"成都市 · 四川省"）—— 让人更快建立地理认知
2. **冷知识加图标区分类型**：`📜 由来` / `🏛 文物` / `🎋 风物` —— 让内容有分类感，比一整块文字更像"百科"
3. **占位文案不要只写"资料收录中"**，可以写**具体的缺口**：
   > "还不能确认这里的地标 · 欢迎补一条"
   这比"收录中"更有行动号召力，也让众包有了明确入口

### 3.3 一个具体的图鉴设计（配合受众）

按省分组 + 进度环 + 已收集条目可翻阅：

```
四川省  12/21 ████████░░░░
  ✅ 成都市 20/20
  🔶 乐山市 11/11
  ⬜ 甘孜州 0/18
```

这既是**收集进度的可视化**，也是**众包任务的分配表**（缺口在哪一目了然）。

## 四、受众是谁（这是最该想清楚的一件事）

### 4.1 我的判断：**核心受众是"想认识自己家乡/生活过的地方"的人**

而不是"喜欢拼图的人"。理由：

| 受众 | 规模 | 动机强度 | 我们的匹配度 |
| --- | --- | --- | --- |
| **① 中学生（地理课）** | 大 | 中（要考试） | ⭐⭐⭐ 高：他们**必须**认识中国行政区划 |
| **② 老师（地理教具）** | 小 | **高**（备课刚需） | ⭐⭐⭐ 高：需要能投屏、能控场的工具 |
| **③ 在外地/国外的人** | 中 | **很高**（思乡） | ⭐⭐⭐ 高："拼出我的家乡"正是他们 |
| **④ 地理爱好者 / 收集控** | 中 | 高（喜欢刷完） | ⭐⭐ 中：363 张地图对他们是天然收集物 |
| ⑤ 休闲拼图玩家 | 大 | 低（随时换） | ⭐ 低：他们不会为"认识地理"留下 |

**结论：①②③ 才是我们的用户，⑤ 不是。**

### 4.2 对症下药（按受众给具体做法）

| 受众 | 他们真正要什么 | 我们应该做什么 |
| --- | --- | --- |
| **中学生** | 考试能用的信息 | 卡片里给**面积、位置、所属**（已有一半）；加"这个市有几个县"这种考点；难度分级（简单模式只拼大块） |
| **老师** | 上课能投屏、能控场 | **大字号模式**；"展示全图"按钮（不玩，直接看）；可隐藏冷知识（避免剧透讨论） |
| **在外地/国外的人** | 情感连接 | **"拼出我的家乡"**（已做）+ 分享卡带家乡名（已做）→ 强化这条线 |
| **爱好者/收集控** | 看得见的进度 | 总进度 + 成就（已做）+ **图鉴**（待做） |

### 4.3 我建议**放弃**的人群

- **纯休闲玩家**：他们来了就走，不构成留存
- **"刷分"玩家**：他们要求排行榜、防作弊、服务端——我们做不了也不该做

> **一句话**：把力气花在"想认识地理的人"身上，而不是"想打发时间的人"。

## 五、给"没钱的学生"的落地顺序

| 顺序 | 做什么 | 成本 | 收益 |
| --- | --- | --- | --- |
| 1 | **上免费托管**（GitHub Pages）+ 买不买域名随意 | ¥0 | 能被访问 = 一切的前提 |
| 2 | **把"字段来源+核验状态"加上** | 1~2 轮开发 | 让内容可信 → B 端合作的前提 |
| 3 | **开放众包**（Issue 模板 + 认领一个省） | 半天 | 分摊内容成本，且让项目"有人参与" |
| 4 | **图鉴**（按省进度） | 1~2 轮开发 | 把 3214 条内容变成收集动机 |
| 5 | **探国内源**（国家地名信息库 API） | 你来做，我做接入 | 可能一次性解决 funFact 的批量获取 |
| 6 | 内容补齐 | 40~50 轮 | 护城河 |

> **第 5 条特别重要**：国家地名信息库有官方的「地名含义/由来」字段，
> 如果它在国内可访问，那 funFact 这一项就能**批量、权威**地拿到，
> 而不是靠百科逐条抓。这是最值得你先去试的一件事。
